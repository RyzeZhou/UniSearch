# 三个后端各能提供什么 → 可筛维度 → 候选筛选器

> 实测日期 **2026-09-28**，本机（win10_vm），三个后端**都装着、都在跑**。
> 协议细节见各自的唯一事实来源：`EVERYTHING-IPC-VERIFIED.md` / `ANYTXT-RPC-VERIFIED.md` /
> `ZOTERO-LOCAL-API-VERIFIED.md`。**本文只回答一个问题：有了这些，筛选器能筛什么。**
> 标记约定：✅ 本机实测通过；❌ 实测不支持；⚠ 未验 / 有条件。

---

## 0. 本机实际装了什么

| 后端 | 状态 | 地址 | 规模（实测） |
|---|---|---|---|
| Everything | 运行中 | IPC 窗口类（`EVERYTHING_TASKBAR_NOTIFICATION`） | 查 `txt` → 260 条 |
| AnyTXT | 运行中，**索引已加载** | **JSON-RPC `127.0.0.1:9924/rpc`**（`anytxt.v1.*`）；MCP `9924/mcp`；Web UI `0.0.0.0:9921` | 全盘 3000+ 条（仍在建索引） |
| Zotero 7 | 运行中 | `127.0.0.1:23119` | **44 顶层条目**（34 期刊论文 + 6 预印本 + 1 笔记…）+ 65 附件、**16 个标签**、**3 个集合** |

⚠ **AnyTXT 的 9921（Web 界面）绑在 `0.0.0.0`（全网可达）**，9924 只绑 127.0.0.1
（且非 loopback 的 Host/Origin 会被拒 403）。如果这台机器在共享网络里，9921 那个 Web 界面是
**别人也能访问**的 —— 值得知悉（我们不用它）。

⚠ **AnyTXT 的 SDK 功能受许可证控制**（文档原话：`the SDK feature must be enabled by the current
license`）—— 不是装了就一定有。Provider 的健康探针要能把这个区分开。

## 2. 哪些过滤条件能**下推到后端**（决定"点一下标签要不要重查"）

| 过滤维度 | Everything | AnyTXT | Zotero |
|---|---|---|---|
| 关键词 | ✅ | ✅ `pattern` | ✅ `q=` |
| 短语 | ⚠ | ✅ `"两个词"`（引号是定界符） | ✅ `q="…"` |
| 排除词 | ✅ `!` | ✅ `!`（实测 7 → 4 条） | ⚠ |
| 扩展名 | ✅ `ext:` | ✅ `filterExt`，**`*.md;*.txt` 与 `md;txt` 两种写法都行** | ❌ |
| 目录 / 路径 | ✅ `path:` | ✅ `filterDir`，**必须显式给盘符**（传空被强制成 `C:`） | ✅ 集合 `collection/<KEY>` |
| 时间范围 | ✅ `dm:` | ✅ `lastModifyBegin/End`（Unix 秒） | ❌（`since=` 是版本号不是日期） |
| 大小范围 | ✅ `size:` | ❌ | ❌ |
| 正则 | ✅ | ❌ **不是正则**：`[ic]`、`s.miconductor` 都 0 条；`\|` 是它自己的 OR 不是交替 | ❌ |
| 排序 | ✅ | ⚠ `order`（取值语义待验） | ✅ `sort=dateAdded/title/creator/date` |
| 总数 | ✅ | ✅ `Search` 返回 `count` = 总数 | ✅ 响应头 `Total-Results` |

**一句话**：Everything 的强项是**文件名 + 路径 + 时间/大小**；AnyTXT 的强项是**正文内容**；
Zotero 的强项是**元数据（类型/标签/集合/作者/年份）**。三边几乎不重叠 —— 这正是要分模板的原因。

## 3. 由这些能长出哪些筛选器

### A. 现在就能做（Everything，不用等新后端）

现有的 4 个（`生信相关` / `3D/CAD` / `笔记本` / `配置`）已经覆盖了"按扩展名分堆"这条路。
还能补的：`最近一周改过的`（`dm:` 下推）、`大文件`（`size:` 下推）。

### B. AnyTXT 解锁的（Everything 下**根本没法存在**）

| 候选标签 | 依据 | 下推？ |
|---|---|---|
| **仅正文命中** | 文件名里没有关键词、只有正文里有 | ✅（本身就是内容搜索的语义） |
| **最近改过的文档** | `lastModifyBegin/End` | ✅ 下推 |
| 任意现有的扩展名分组 | `filterExt` | ✅ 下推 |

**"仅正文命中"是最有价值的一个** —— 它回答的是"我记得内容但忘了文件名"，这是 Everything 永远做不到的。

### C. Zotero 解锁的（文献场景）

| 候选标签 | 依据 | 下推？ |
|---|---|---|
| 期刊论文 / 预印本 / 笔记 / 附件 | `itemType` | ✅ |
| 按真实标签：`蛋白设计` `分子口袋` `亲和力` `病毒` `机器学习`… | `tag=` | ✅ |
| 某个集合：`AI发酵` `抗体成药性` `模型文章` | `collection/<KEY>` | ✅ |
| 有 PDF 全文的 | `itemType=attachment` + `contentType` | ✅ |
| 某年份之后 | `date` | ❌ **只能前端筛**（API 不支持日期过滤） |

### D. 跨后端通用的（该进所有模板）

`全部` / `文件夹`（仅 Everything）/ 按扩展名的那几组（Everything + AnyTXT，Zotero 下无意义）。

## 4. 对模板分组的直接启示

看真实的库就知道模板该怎么分了 —— **不用凭想象设计**：

| 模板 | 装什么 | 默认给谁 |
|---|---|---|
| **文件查找** | 生信相关 · 3D/CAD · 笔记本 · 配置 · 最近改过的 | Everything |
| **全文查找** | 仅正文命中 · 最近改过的 · 生信相关（内容里提到也算） | AnyTXT |
| **文献查找** | 期刊论文 · 预印本 · 蛋白设计 · 分子口袋 · 亲和力 · AI发酵 · 抗体成药性 | Zotero |

**最关键的观察**：`生信相关` 这种按扩展名的标签，在 Zotero 下**一个都不该出现**（文献条目没有扩展名）；
反过来 `蛋白设计` `AI发酵` 在 Everything 下也没意义。**这就是"按后端分叉"的全部理由。**

## 5. 还没验的（真要动手前得补）

1. AnyTXT `order` 各取值的实际排序语义（本轮只验了不报错）；
2. AnyTXT `fid` 跨重索引是否稳定（决定 Metadata 里要不要同时存 path 兜底）；
3. Zotero `q=` 的 `-` 排除语法；
4. Zotero `zotero://select` URI 的精确格式（"在 Zotero 中打开"要用）；
5. Zotero `links.enclosure` 在各种条目类型下的稳定性（本机实测 `C:\Users\zhou\Zotero\storage\…`，
   与 win11_host 的 `G:\数据库\Zotero\storage\…` **不同机器不同路径**，不能写死）；
6. Zotero 的"仅正文命中"能否与 AnyTXT 同构表达（目前看**不能** —— Zotero 不返回命中片段）。

## 6. 由用户拍板的 UI 口径

### 6.1 Zotero 标签 = 「展开式筛选器」，不摊开

> 用户原话（2026-09-28）：**"Zotero 标签我觉得可以做另外的一种筛选器，不直接摊开在上面，
> 而是有一个小三角，点开之后再展示全部标签，顶部只显示已经选择的标签。"**

要点（实施时照这个做，届时把本节搬进 `docs/spec/UI-SPEC.md`）：

- **标签栏上只占一个位置**，不把 16 个标签平铺出来 —— 否则标签栏会被文献标签撑爆，
  而它们在 Everything / AnyTXT 下本来就该藏起来；
- **顶部只显示已选中的标签**（0 个选中时显示一个占位名，如"标签"）；
- **点小三角展开**全部标签（多选），选中的打勾；
- 语义上它是**一个筛选器**（多选 = 多个 `tag=` 条件），不是一排筛选器 ——
  这与现有"一个标签一个 `FilterDefinition`"的模型不同，**是新的筛选器类型**。

⚠ 这条牵动 `FilterDefinition` 的模型（现在一个定义 = 一个固定条件，没有"可多选的候选值"这种形态）。
真要做，需要在筛选器模型上加一类"**值域型筛选器**"（候选值来自后端，如 Zotero 的 `/tags`、
`/collections`）。**建议先做 Provider，把标签真列出来之后，再回头定这个模型。**
