# UI 规格：Win11 美术 + Win10 紧凑布局 + 键鼠友好

> 需求原话：**"偏传统 UI 的紧凑布局，但美术设计可以现代一些 —— 用 Win11 的样式、Win10 那样的布局，键鼠友好。"**
> 技术选择：**WPF + .NET 8 + `WPF-UI`(MIT)**（EverythingToolbar 同款；Mica/FluentWindow/控件样式现成，密度自己定）。
> 不用 WinUI 3：需要 Windows App SDK 打包与运行时，且默认度量偏松，改紧凑反而更费劲。

## 1. 设计原则（冲突时的裁决顺序）

1. **信息密度优先**：一屏能看到的结果数 > 呼吸感。行高、间距按 §2 的硬数值执行，禁止"看起来更舒服"地放大。
2. **键盘是第一等公民**：任何鼠标能做的都有键；焦点永远可见；不需要 Tab 遍历结果列表。
3. **视觉现代但克制**：只用 Mica 背景 + 圆角 + 强调色 + 深浅色跟随系统；**不做**大模糊、动画铺陈、卡片投影堆叠。
4. **不注入 Explorer**：UI 永远是独立进程窗口（`UniSearch.Host`），Shell 侧只负责把上下文送进来。

**列宽默认值**（`ColumnCatalog`，同时是"恢复默认列"的依据）：
名称 180（**填充列**：窗口变宽时它吃掉剩余空间，下限是默认值）· 路径 230 · 扩展名 70 ·
大小 72（右对齐）· 修改时间 136 · 类型 68 · 来源 80。
默认可见列 = 名称/路径/大小/修改时间/类型（扩展名与来源默认隐藏，右键列头勾选）。
这五个的默认宽度之和 + 名称列的填充，刚好塞进 1280 宽的窗口 —— 一打开就能看见大小和时间，
不用先去拖列宽。

**字体**：`Segoe UI Variable Text, Segoe UI, Microsoft YaHei UI, Microsoft YaHei, SimSun`。
**末尾的中文字体不能省**：Segoe UI 没有汉字，只写它的时候 WPF 的系统回退会挑到
Yu Gothic UI 之类的**日文字体**，"直""骨"这类字一眼能看出是日文字形（实测踩到）。
等宽场景用 `Font.Mono`（`Cascadia Mono, Consolas, Microsoft YaHei UI, Courier New`，同样带中文回退）。
图标：`Segoe Fluent Icons`（码点见 §6）。
`FontFamily` 设在 `Window` 上，靠继承覆盖所有子元素 —— 逐个 TextBlock 写迟早会漏。

## 3. 布局（三栏：来源 | 详细列表 | 预览）

```
┌────────────────────────────────────────────────────────────────────────────┐
│ 🔍 [ transformer attention                                          ] ⚙  │  搜索行 36（全宽）
├───────────┬────────────────────────────────────────────────┬───────────────┤
│ 来源    « │ 全部(236) 文件(89) 图片(1) 代码(100) 生信相关(13)│ 预览 + 摘要 › │  筛选行 28
│  Everything│ 3D/CAD(3) 配置(23)   ← 换行而不是横向滚动        │               │
│   默认 236 条│ 名称▲ │ 路径 │ 大小 │ 修改时间 │ 类型          │  chat_pdf.py  │
│           │ 📄 chat_pdf.py │ C:\…\pdfkit… │ 3.4 KB│ 2026-09-12 │ 文件         │
│           │ …（虚拟化，一屏 26 行 @20px）                    │               │
├───────────┴────────────────────────────────────────────────┴───────────────┤
│ 找到 236 条 · 来源 Everything。Enter 打开 · Shift+Enter 所在目录 · 右键更多 │  状态条 22
└────────────────────────────────────────────────────────────────────────────┘
```

**筛选行属于列表，不属于窗口**：它在**中间列内部**、与列表左边缘对齐。
横跨整个窗口（从左栏上方开始）会让它看起来像"管着来源栏"——实测用户就是这么误读的。
它由 `WrapPanel` 承载：标签多了换行，**不做横向滚动**（滚动条会吃掉一行高度，
而且"有标签被藏在右边"用户根本看不出来）。

**左栏两态**（不是"有或无"）：

| 形态 | 宽度 | 内容 | 切换 |
|---|---|---|---|
| 大 | 188（可拖，最小 132） | 图标 + 名称 + 状态（"236 条"/"未参与"）+「默认」标 | 头部 `«` 按钮 / `Ctrl+B` |
| 小 | 56 | 只有后端图标 + 下面一行数量（**超过 9999 写 `>9999`**） | 同上 |

**右栏收起后留一条 22px 的"把手"**（带展开按钮）：收起即消失的话，用户只剩快捷键能把它叫回来。

**为什么是平铺单表（而不是分组）**：口径对齐 Everything 与资源管理器"详细信息"视图 ——
一列一个字段、列头可点排序、列宽可拖、列可增减与左右移动。原来的"按分类分组、每组上限 24 行"
在信息密度上是净损失：日志里能看到 `files:24/102`，用户搜 `pdf` 时 102 个文件只看到 24 个。
分类改由**筛选行**（硬过滤）+ **类型列**表达。

**三栏各自的职责**（改任何一栏前先读这条）：

| 栏 | 管什么 | 不管什么 |
|---|---|---|
| 左：来源 | **搜哪些后端**（进 `SearchQuery.ProviderScope`）；点击 = 本次只搜它，再点取消限定 | 不负责过滤已返回的结果 —— 没被选中的后端根本不进调度 |
| 中：列表 | 呈现与排序：列宽/列序/可见列/排序键 | 不改变后端返回什么 |
| 右：预览 | 选中项的内容预览 + 摘要（类型/大小/时间/来源） | 不做编辑 |

左栏用 `Ctrl+B` 在**大/小两态**间切换；右栏用 `Ctrl+J` 展开/收起（收起 = 留一条 22px 把手）。宽度用列宽表达（而不是把列删掉），所以用户拖过的宽度记得住。



**筛选行**（列表上方那排标签）来自两处：内置分类（`CategoryEngine`）+ 自定义筛选器（`filters.json`，格式见 [FILTERS.md](FILTERS.md)）。点标签 = 硬过滤；自定义筛选器会被翻译成 `ext:` / `kind:` 查询条件 —— **后端先过滤**，而不是把全量结果搬回来再筛。筛选器定义里的 `providers` 字段决定它只在哪些后端下出现，这就是"不同后端用不同筛选器"的落点。

**行的实现（关键取舍）**：一行 20px 只放一个字段。原来的"单行双列"（标题 + 右侧大小）
被列取代 —— 多出来的宽度全部还给字段本身，靠**列宽可调**而不是靠"塞进同一行的右侧"。

窄窗口（<900px）：名称列自动填充的下限是它的默认宽度（180），再窄就让水平滚动条出现；
不自动隐藏列（隐藏了用户会以为列没了）。


## 4. 键鼠交互契约

### 4.1 全局（窗口未聚焦时）

| 键 | 行为 | 实现备注 |
|---|---|---|
| `Ctrl+F`（在 Explorer/桌面前台中） | 唤出本窗口并限定当前目录 | ShellContext：`RegisterHotKey` + Flow DialogJump 路线（REF-2 §2.1） |
| `Win+Alt+Space`（可自定义） | 唤出，范围=全局 | 同上，不改 Explorer |
| `Esc`（已聚焦时） | 隐藏窗口并把焦点还给来源窗口 | 记录 `OwnerWindow` |

### 4.2 窗口内导航

| 键 | 行为 |
|---|---|
| `↑ ↓` | 移动选中项（表格里就是相邻行） |
| `PgUp PgDn` | 半屏滚动 |
| `Home End` | 首/末项 |
| `Enter` | 打开（文件=ShellExecute；条目=其 Uri；文件夹=在 Explorer 中打开） |
| `Ctrl+Enter` | 以管理员运行（UAC 取消不算错误，见 REF-1） |
| `Shift+Enter` | 打开所在目录并选中 |
| `Alt+Enter` | 属性对话框 |
| `Ctrl+Shift+Enter` | 在终端中打开所在目录 |
| `Tab` | 搜索框内有补全候选时先补全（`AutoCompleteText`，Everything 式 typeahead），无候选时切到下一个**分类标签** |
| `Ctrl+1..9` / `Alt+1..9` | 切到第 N 个分类（`Ctrl+0`=全部） |
| `Ctrl+C` | 复制 `CopyText ?? Path ?? Title` |
| `Ctrl+Shift+C` | 复制文件名 |
| `Ctrl+B` | 左栏大/小形态切换（大 = 名称+状态，小 = 图标+数量） |
| `Ctrl+J` | 右栏（预览）开合 |
| `Ctrl+Backspace` | 删除搜索框最后一个词段 |
| `F12` / `Ctrl+,` | 设置 |
| `Ctrl+Shift+I` | 诊断面板（Provider 调度结果、耗时、被跳过原因） |
| 点列头 | 按该列排序；同列再点换方向（大小/时间首次点击是降序） |
| 拖列头边缘 | 改列宽（松手后落盘，不重跑查询） |
| 拖列头本身 | 列换位（`AllowsColumnReorder`，换位后回写 `Vm.Columns`，随窗口关闭落盘） |
| `Shift` + 滚轮 | **结果表横向滚动**（内容比视口宽时）；不带 Shift 仍是纵向滚动。Windows 通用习惯（资源管理器/浏览器/Office 同） |
| 右键列头 | 增减列 / 左右移动列 / 恢复默认列布局 |
| 右键结果行 | 宿主默认动作 + Provider 领域动作（危险项按住 Shift 才出现） |
| 中键点击 | 在新实例中打开（如浏览器新标签），否则等同 `Shift+Enter` |
| 鼠标拖出 | `SetFileDropList` 拖到 Explorer/编辑器（REF-1 行为清单） |
| 悬停 | ToolTip 全路径（+ 正文命中摘要） |

**焦点可见性要求**：选中行必须有 2px 强调色左边框 + 底色变化；键盘焦点与鼠标悬停态必须视觉可区分（不能都只有一个浅灰底）。

### 4.3 输入体验

- 输入即搜（debounce **120ms**，Everything 快所以可以更激进；慢后端靠占位区）。
- 新输入立即让旧请求作废：Broker 内部单一活动请求 + `RequestId` 校验（已在 `SearchBroker` 实现）。
- `Tab` 在搜索框内 = 接受当前高亮项的 `AutoCompleteText`（Everything 式 typeahead）。
- 文本渲染：主窗口 `TextOptions.TextFormattingMode="Display"`（GDI 式度量，对齐资源管理器观感；默认 Ideal 会偏宽偏糊）。
- 空输入：Explorer 上下文下列举当前目录；全局上下文显示"最近使用"（来自 `IUsageStore.GetTopKeys`）。

## 5. 视觉细节（Win11 皮 / Win10 骨）

- **行态**：hover = `Brush.Subtle.Hover`（7.8% 黑），选中 = `Brush.Selection`（强调色 14%）。
  20px 行高下不加交替底色 —— 列本身就提供了扫读的纵向参照，再叠一层斑马纹只会更花。
- 命中片段用 **加粗 + 强调色**（移植 `HighlightedText` 附加属性的 Run 复用优化，见 REF-1 §2）。
- 列头：12 DIP 灰字（`Font.Size.ColumnHeader`，只管中间列）；当前排序列**加粗**并跟一个 ▲/▼（9 DIP 强调色）；hover 显示右侧拖拽热区。
- 中间结果行 12 DIP（`Font.Size.ResultRow`）、筛选标签 12 DIP（`Font.Size.FilterTab`）—— 中间列专用，
  左右栏沿用共享字号（Primary 11 / Secondary 10.5 / Chip 10），互不影响。
  中间列三档刻意取同一个值 **9pt = 12 DIP**：资源管理器与 Everything 的列表文字与列头本来就同档。

> **单位提醒（2026-09-20 实测踩到）**：XAML 的 `FontSize` 是 **DIP（1/96 英寸）**，不是磅。
> `1 pt = 1.333 DIP`，所以 `FontSize="12"` = **9pt**、`FontSize="8.5"` = 6.4pt。
> 本机基准（`SPI_GETICONTITLELOGFONT` 实测）：系统 UI 与资源管理器列表字体 =
> **Microsoft YaHei UI 9pt = 12 DIP**；搜索框 12.5 DIP = 9.4pt。
>
> **⚠ 光有令牌不等于生效（2026-09-20 实测踩到）**：WPF-UI 4.0.3 的 `ControlsDictionary` 里带一个
> 隐式 `TextBlock` 样式且设了 `FontSize=14`，而"样式 setter"优先级**高于"属性继承"** ——
> 凡是"容器设字号、子元素靠继承"的写法（结果行、列头、以字符串为 Content 的筛选标签）都会被
> 强行画成 **14 DIP = 10.5pt**，比资源管理器的 9pt 还大，令牌形同虚设。
> 修法：`App.xaml` 里**直接**声明一份不设 `FontSize` 的隐式 `TextBlock` 样式盖掉它；
> 单元格与列头另外显式写出 `FontSize`。
> **规则：靠继承取字号的地方一定要量出来验证，不能只信令牌。**
- 分类标签：文字 + 计数徽标，选中态为浅底填充（`Brush.Selection`）。
- chips（来源/正文命中）：高度 16、圆角 3、字号 10px、Tone 决定前景色（`Info`/`Success`/`Accent`…）。
  平铺单表后 chips 不再进列表（会撑破行高），改在右键菜单与预览摘要里体现。
- 左栏来源项：图标 + 名称 + 状态（"186 条"/"未参与"/"已在设置中禁用"），
  属于设置里"随输入自动搜索"集合的项带一个"默认"小标。
- 深色/浅色跟随系统；**不使用**亚克力大面积铺底（只在窗口背板用 Mica）。
- 加载态：状态条写"搜索中…"，列表保持上一次结果（不要清空成白屏）。

## 7. 无障碍与本地化

- 所有可点击元素有 `AutomationProperties.Name`；结果行 `Name = "标题, 类型, 路径"`。
- 键盘操作不依赖颜色区分（选中态同时改变边框与字重）。
- 中文/日文路径不做特殊截断策略（统一 `TextTrimming=CharacterEllipsis` + ToolTip）。
- 文案集中到 `Resources/Strings.zh-CN.resx`，英文为兜底（参考 ET 的 `FilterNames`/`Localizer` 做法）。

## 8. 反例（明确不做）

- ❌ 大圆角卡片 + 大量留白的"启动器美学"（Flow/CmdPal 默认观感）——与"密集可扫读"冲突。
- ❌ 把每个 Provider 的结果做成独立区块争夺纵向榜单（后端切换交给左栏来源，见 §3）。
- ❌ 结果行内放多个按钮（Hover 才出现的按钮会破坏 20px 密度；动作统一走右键 + 快捷键）。
- ❌ 在 UI 里做"正在索引 X%"的大横幅 —— 放进状态条一行文字即可。
- ❌ 自动隐藏列（窗口变窄时）—— 列"自己消失"比出现水平滚动条更让人困惑。
