# 筛选器定义（filters.json）

> 结果表上方那排标签 —— **全部 / 文件 / 文件夹 / 图片 / 生信相关 / 3D-CAD …** —— 就是筛选器。
> 内置的那几个（文件、图片、文件夹…）由分类引擎负责，**自定义的**来自 `filters.json`。

## 为什么要做成定义文件

筛选器集合是会长的东西：今天要"生信相关"（pdb/cif/fasta…），明天可能要"3D 打印"（stl/obj/3mf）、
"设计稿"（fig/sketch）、"字幕"（srt/ass）。把这些写死在代码里，每加一组就得改代码、重编译、重发版。

所以：**匹配规则写成 JSON，程序读它**。你加一组扩展名，保存，重启 UniSearch，标签栏里就多一个。

## 两个文件，后者覆盖前者

| 文件 | 作用 | 会不会被覆盖 |
|---|---|---|
| `<程序目录>\filters.json` | 程序自带的模板（几个示例） | **会** —— 更新程序时被新模板替换 |
| `%LOCALAPPDATA%\UniSearch\filters.json` | 你自己的 | 不会 |

**同 id 的定义以后者为准**，所以你可以在自己的文件里"改掉"模板里的某一组（例如把"生信相关"的扩展名加几个）。

改完不用改设置：**重启 UniSearch 生效**。设置窗口 →「筛选器」→「编辑我的筛选器」会直接打开你那份
（文件不存在时自动用模板初始化一份，省得对着空文件发呆）。

## 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 稳定标识。会出现在配置与日志里，**改名等于换一个筛选器**。非字母数字会被替换成 `-` |
| `name` | ✅ | 标签上显示的名字 |
| `extensions` | ⬜ | 扩展名数组。带不带点都行、大小写都行（`.PDB` / `pdb` / `PDB` 等价） |
| `kinds` | ⬜ | 结果类型数组：`File` `Folder` `Image` `Video` `Audio` `ArchiveEntry` `Application` `BibliographicItem` `Note` `WebPage` `CodeSymbol` … |
| `namePattern` | ⬜ | 文件名正则（不区分大小写），例如 `^log-\d+\.txt$` |
| `providers` | ⬜ | 只在这些后端下显示，如 `["everything"]`。**留空 = 所有后端都显示** |
| `order` | ⬜ | 标签栏次序（内置分类占 0–900，默认 500） |
| `glyph` | ⬜ | 图标码点（Segoe Fluent Icons，如 `E9D9`）。不给就用通用图标 |
| `description` | ⬜ | 说明文字，鼠标停在标签上能看到 |
| `hidden` | ⬜ | `true` = 不在标签栏显示（留给"别名"用） |

**匹配是并集**：`extensions` 命中、或 `kinds` 命中、或 `namePattern` 命中，这条结果就算属于该筛选器。
三个条件至少要写一个 —— 一个都不写的定义会被当成写错，剔除并在日志里报出来。

## 例子

### 1. 最常用：一组扩展名

```json
{
  "id": "bioinformatics",
  "name": "生信相关",
  "order": 500,
  "description": "结构 / 序列 / 比对 / 注释类文件",
  "extensions": ["pdb", "cif", "mmcif", "pse", "fasta", "fa", "fastq", "sam", "bam", "vcf", "gff", "gtf"]
}
```

### 2. 只给某个后端用（"不同的搜索后端用不同的筛选器"）

```json
{
  "id": "content-hits",
  "name": "仅正文命中",
  "providers": ["anytxt"],
  "kinds": ["File"]
}
```

`providers` 里写了 `anytxt`，那么在用 Everything 搜的时候这个标签**根本不出现** ——
因为对文件名索引来说"仅正文命中"没有意义。这就是筛选器按后端分叉的机制。

### 3. 按文件名而不是扩展名

```json
{
  "id": "logs",
  "name": "日志",
  "namePattern": "^(log|trace|error)[-_].*\\.(txt|log|jsonl)$",
  "extensions": ["log"]
}
```

## 筛选器模板：标签栏怎么组织（v2）

> 状态：**F0 + F1 已落地** —— Core 层（schema / 两文件独立合并 / 解析链 / 兼容回退，单测 6 条）
> 与 UI 层（标签栏最左的模板锚点、切换、钉住、持久化，`--selftest-templates` 7 项断言）都通了。
> **尚未接入**：热重载（F2）、下推映射（F3）、设置窗里的模板编辑器（现在还是手写 JSON）。
> 程序自带的 `filters.json` **刻意还没有** `templates` 节 —— 所以现在跑起来的行为与从前一致
> （实测：主窗渲染与改造前**逐像素相同**）。

定义一多，全平铺在标签栏里就是一长排；而且"我现在想看哪几桶"是随场景变的 ——
找数据文件时要生信/3D/配置那几组，查文献时要条目类型/标签。**模板 = 一组筛选器的有序引用**，
可整体切换、可按后端给默认值。同一个文件里再加一个 `templates` 数组即可：

```json
{
  "version": 2,
  "filters": [ /* 原样不动 */ ],
  "templates": [
    { "id": "files",   "name": "文件查找", "order": 100,
      "filters": ["bioinformatics", "configs"], "defaultFor": ["everything"] },
    { "id": "minimal", "name": "极简",     "order": 900, "filters": [], "defaultFor": ["*"] }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` / `name` / `order` | ✅ | 同筛选器的口径；`id` 稳定，改名 = 换一个模板 |
| `filters` | ✅（可为空数组） | 引用筛选器的 `id`，**只引用不复制**；同一定义可进多个模板 |
| `defaultFor` | ⬜ | 该模板是哪些后端的默认；`"*"` = 全局兜底（全局视图也走它） |
| `providers` | ⬜ | 只在哪些后端下**可选**（下拉里出不出来）；留空 = 所有后端可选 |

规则：

- **模板与筛选器各自独立合并**：两份文件同 id 的模板后者为准（**整条替换**，不做字段级合并）；
  用户文件里只写 `filters` 时，程序模板的 `templates` 照样生效，反之亦然。
- **顺序以模板里的引用先后为准**（模板存在的意义就是"有序引用"），不再按定义的 `order` 排。
- **双重显隐**：模板内可见 = 模板引用的 id ∩ 筛选器自己的规则（`providers` 不适用就藏、`hidden` 不显示）。
- **激活模板解析链**（每个后端独立）：钉住的 → 部署级默认 → `defaultFor` 认领该后端（order 小者胜）
  → `defaultFor: ["*"]` → **回退平铺**。
- **没写 `templates` 节 = 100% 现状**：所有未 `hidden`、且适用该后端的定义按 `order` 平铺。
  写了节却没有任何模板认领当前后端时，同样回退平铺（绝不把标签栏变空）。
- **写错了不崩**：引用了不存在的筛选器 → 剔除该引用并记问题（不整条丢模板）；两个模板抢同一个后端
  → order 小者胜并记问题。日志里搜 `[filters]`。

### 怎么切模板（界面）

标签栏**最左**有一枚模板锚点（漏斗图标 + 当前模板名），点一下弹下拉：

- 列出**当前后端可选**的模板（`providers` 字段管这个），当前那个打勾；
- 最后一条「跟随后端默认」= 取消钉住，回到解析链；
- **没有 `templates` 节时锚点整个不显示** —— 不给人一个按不动的按钮。

**钉住**：手动选一个模板 = 把它写进 `settings.filterTemplates.<providerId>`，之后**切来源不再自动跟随**；
点「跟随后端默认」就删掉这个键、恢复跟随。

**多后端怎么办**：来源栏本身是单选，所以常态就是"某一个后端"。只有"默认来源集合"（`search.autoSearchProviders`）
被填了多个、或清空时才算"没有某一个后端" —— 那时锚点走 `defaultFor: ["*"]` 兜底，手动切换只作用于本次会话
（没有可归属的后端 id 就没地方钉）。**刻意为多后端设计模板语义这件事没做。**

切换模板**不重新搜索**：只重算标签栏显示哪几个（`--selftest-templates` 里用查询次数断言了这一点）。
唯一的例外：当前选中的自定义筛选器被新模板藏掉了 → 自动退回「全部」，否则会出现"标签栏一个高亮的都没有、
但查询串还在按那个筛选器过滤"。

## 写错了会怎样

不会崩，也不会静默吞掉：

- **整份 JSON 解析失败** → 这一份被跳过，其他文件照常加载，日志里写清楚哪一行错了；
- **某条定义有问题**（没有 id、类型名不认识、正则不合法、一个条件都没写）→ 只剔除这一条，
  日志里说明原因，其他定义照常工作；
- 日志在 `%LOCALAPPDATA%\UniSearch\host.log`，搜 `[filters]`；
  设置窗口的「筛选器」一节也会写"其中 N 条定义有问题"。

## 与内置分类的关系

- 内置分类（文件/文件夹/文档/图片/视频/音乐/应用/压缩包/代码/正文命中/网络/文献/笔记/其他）
  由 `CategoryEngine` 按扩展名表 + 结果类型判定，**不从这个文件读**；
- 自定义筛选器与内置分类**并列显示**在同一排标签里，按 `order` 排序；
- 点内置分类 = 按分类硬过滤；点自定义筛选器 = 把它翻译成 `ext:` / `kind:` 查询条件
  （所以后端会**先**过滤，而不是把整库结果搬过来再筛）。两者在状态条的查询日志里都能看到实际查询串。

## 值域筛选器（候选值来自后端，不进这个文件）

上面那套是"**宿主定义**筛选器"：值域写在 `filters.json` 里（一批扩展名、一个类型）。
但有第三种筛选器，它的**值域只有后端自己知道** —— 典型就是 Zotero 的标签：
用户随时在 Zotero 里打标签，宿主这边没有任何同步来源，写死一份列表第一天就对不上了。

它由 `IFacetProvider` 声明，**不在 `filters.json` 里配置**：

```csharp
// SDK：后端声明自己能提供哪些值域
public interface IFacetProvider
{
    IReadOnlyList<FacetDescriptor> Facets { get; }
    ValueTask<FacetValues> GetFacetValuesAsync(string facetId, SearchContext ctx, CancellationToken ct);
}
```

界面上的样子（刻意与上面两种都不一样）：

```
[标签 ⌄]  [机器学习 ×] [智能体 ×]  |  全部(60)  文档(35)  期刊论文(21) …
   ↑           ↑                         ↑
 点开才展开   顶部只显示已选的           内置分类与宿主筛选器照旧
```

- **不摊在标签栏上**：候选值可能有上百个，摊开就没法看了。锚点是一枚"点开才展开"的按钮（带小三角）；
- **顶部只回显已选值**：每个带 `×` 可单独摘掉，另有「清空」；"当前在筛什么"始终可见；
- **候选值是懒加载的**（点开才去读），因为取一次要真跑一趟后端；
- **换来源就清空**：Zotero 的标签在 Everything 下毫无意义，与"换来源时标签选择归零"同一条理由。

- 展开面板里的每一行是候选值；**候选值有两个身份**：给人看的 `Value`（"R语言"）
  与下推给后端的 `Key`（思源的笔记本 id）。两者**可以不同**，也必须分开存 ——
  第一版把显示名当下推值送过去，`box IN ('R语言')` 永远 0 条，
  而界面上 chip 正常、勾选正常，只有结果是空的（实测踩到）。Zotero 的标签恰好两者相同，
  所以那是思源才暴露出来的。

### 调度与下推（重要）

带值域选择的查询会让 `ProviderSelector` **跳过所有不实现 `IFacetProvider` 的后端**
（`SkipReason.NotApplicableToFacetFilter`），并且**刻意不做前端近似过滤**：
候选值是从 Zotero 拿的，拿它去匹配 Everything 的文件行只会得到空列表 ——
用户看到"选了标签就什么都没有"，而真相是这个后端根本不懂标签。

Zotero 的下推（实测口径见 `research/ZOTERO-LOCAL-API-VERIFIED.md` §4.10）：

| 口径 | URL | 说明 |
|---|---|---|
| 任一命中（默认） | `tag=A \|\| B` | 单个参数值里放布尔式 |
| 全部命中 | `tag=A&tag=B` | 重复参数名 = AND |
| 值本身 | **原样送，不加引号** | 引号在本地端点上不是精确短语语法，实测返回 0 条 |

**判据用"真的选了值"**（`QueryFilters.HasFacetSelection`），空壳（域在、值空）不算 ——
否则用户把最后一个勾去掉的一瞬间就会少一个后端，而他其实什么都没改。

## 还没做的

- `namePattern` 目前只在前端过滤（结果集）层面生效，还没有下推到后端查询；
- 筛选器之间不能嵌套/组合（例如"生信相关 且 最近一周"）；
- 没有图形化的筛选器编辑器（就是手写 JSON —— 这是刻意的，避免为一个低频操作做一整套 UI）。
